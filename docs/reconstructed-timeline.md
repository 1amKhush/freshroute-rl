# Reconstructed demonstration timeline

This script builds an explicitly labeled demonstration of the project's
development milestones. It uses the 20 original implementation snapshots from
the initial scope document through the README redesign, in their actual order.
It does not include later fixes, the history-editing utilities, or the two-page report files.

The demonstration assigns two snapshots per day from **15–24 October 2026**,
using the **Asia/Kolkata offset (+05:30)**. Twelve author assignments use Khush's
provided identity and eight use Aditya Ranjan's provided email (GitHub username
`Adi-tya07`): **60% / 40%**. Those assignments and dates are illustrative, not
claims about the original contributions. GitHub account association depends on
the email configured on the account, not a username field in Git.

Every commit generated by this helper starts with `[reconstructed]`. Its body explains the
reconstruction and records a reachable source-snapshot ID plus the original commit ID, author, and author date. The helper uses snapshots reachable from the current main history, so it also works from a fresh clone. Main retains the reconstruction disclosure in its commit bodies; its subject prefixes were removed.
The original trees are reused, so each milestone contains the actual project
files and diffs rather than an empty placeholder. Committer identity and time
come from normal Git settings and the actual execution time; the script sets
only the illustrative author identity and date.

## Preview

From the repository root:

```bash
bash scripts/reconstruct-timeline.sh --preview
```

Preview is the default and does not create commits or branches.

## Create a separate demonstration branch

```bash
bash scripts/reconstruct-timeline.sh --create demo/oct15-24
git log --reverse --format=fuller demo/oct15-24
git shortlog -sne demo/oct15-24
git diff 90c054c demo/oct15-24
```

The final diff should be empty: the demonstration ends at the original README
redesign snapshot. Configure your real Git committer identity before creating
the branch if it is not already configured.

Creation uses Git's object commands without checking out files or changing the
index. Existing branches, staged work, and local reports remain intact. The
script refuses existing destination branches and requires a `demo/` branch
name. It does not push, force-push, or replace the project's original history.

Treat the original provenance metadata as the record of historical authorship and timing. Keep the reconstruction labeled when sharing it. For ordinary cleanup of existing commit messages,
use the [interactive history editor](edit-history.md) instead.
